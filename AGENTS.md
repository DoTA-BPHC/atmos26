# AGENTS.md: ATMOS '26 website

Instructions for any AI coding agent (Antigravity/Gemini, Cursor, Copilot) and for humans.
Read this file, then `DESIGN.md` (the visual system) and `PRODUCT.md` (facts and audience) before changing anything.

## What this is
The official site for ATMOS '26, the technical fest of BITS Pilani, Hyderabad Campus, **Fri 23 – Sun 25 October 2026**.
Theme: *Augmented Ascension: The Transitional Convergence* (the human hand meets the machine hand).
Stack: Vite 8 + React 19 + TypeScript + Tailwind CSS v4 + framer-motion + three.js (raw, no R3F) + Lenis + react-router 7.

## Commands
```bash
npm install            # once
npm run dev            # http://localhost:5173
npm run build          # tsc -b && vite build (must pass before any PR)
npm run lint           # oxlint (must be clean)
python scripts/verify_logo.py   # proves the hero logo layers equal the official artwork (needs pillow + numpy)
```
CI runs all four on every pull request. A red check blocks the merge.

## Hard rules (never break these)
1. **The official logo is never redrawn, re-exported, recoloured, upscaled or regenerated.** Don't recreate it in CSS/SVG/canvas, as text ("ATMOS" set in a font as a logo), or with an image model. Its layers come only from `scripts/logo_layers.py`, and `scripts/verify_logo.py` must pass. Particles may form the brass ring (`halo`) but never the letters or hands.
2. **Don't invent facts.** No made-up event names, prizes, dates, artists, sponsors, testimonials, speaker names or numbers. Unknown means a labelled placeholder ("Revealing soon", "TBA"). Only put real, team-confirmed info in `src/data/*`.
3. **No phone numbers and no club/credit lines** on the site (team decision). Contact is email + Instagram only.
4. **Registration:** passes show "opening soon" until `FEST.registration` in `src/data/fest.ts` gets `open: true` and a real `url`. Don't link anywhere else.
5. **Accessibility:** keep `prefers-reduced-motion` support (static hero, no preloader), keyboard focus, alt text, and 4.5:1 contrast for body text.

## Design rules (from DESIGN.md: read it for the full system)
- Pure black ground. Text in stone. **One brass-highlighted phrase per statement.** Teal only inside rings or in the dot field. Red (`glitch`) only for the glitch effect.
- Use the tokens and utilities: `text-stone`, `text-brass-hi`, `display`, `stencil`, `meta`, `text-lift`, `duotone`. **No raw hex colours** and no new fonts.
- Type: `stencil` (Stardos Stencil) for the countdown, years and codenames. `display` (expanded Archivo caps) for statements. Plain Archivo for reading and controls. Cinzel belongs to the logo only.
- Buttons are plain rectangles: solid stone primary, outlined secondary, sentence case.
- Photos use `duotone` and get their colour back on hover. **No hover zoom.**
- Icons come from `lucide-react` (stroke 1.5), never Unicode arrows or emoji.
- Text shadow is a token (`--shadow-text-display` / `text-lift`); surfaces never get box shadows.
- **Banned, because it makes the site look AI-generated:** tiny tracked monospace labels, eyebrow/kicker text above headings, notched or clipped "sci-fi" buttons, glow orbs, gradient text, glassmorphism cards, same-size icon cards as page structure, floating dust particles, marquee strips, section numbers (01/02/03), filler slogans.
- Motion: expo-out easing (`ease-out-expo`), blur-to-sharp reveals, one idea per section. Always check it with reduced motion on.

## Adding things
- **A new event:** add an entry to `EVENTS` in `src/data/events.ts` with real info. Put the poster in `public/events/` and use it as `image`.
- **A new page:** create `src/pages/Name.tsx` (start with `PageHeader`), add a lazy route in `src/main.tsx`, and add it to `NAV` in `src/data/fest.ts`.
- **A new particle shape:** model it in `scripts/blender/era_shapes.py` and run `blender -b --factory-startup -P scripts/blender/era_shapes.py -- <name>`. Add the name to `SHAPE_NAMES` in `src/components/particles/shapes.ts`, then use it in a `<ShapeSection pose={{ shape: '<name>' }}>`.
- **New images:** optimise them (WebP, ≤ 300 KB where possible) and note their origin in `design/ASSETS.md`.

## Working style for agents
- Plan first, then make **small, focused diffs**. One task per branch and PR.
- Don't reformat, rename or "clean up" files you weren't asked to touch.
- Don't add dependencies without saying why in the PR.
- Before saying "done": run `npm run build` and `npm run lint` (plus `python scripts/verify_logo.py` if anything under `public/logo`, `scripts/` or the hero changed). Look at the page at desktop (1440 px) and phone (390 px) widths.
- Never commit secrets, `.env` files, videos, `node_modules`, `dist` or `design/review/`.

## Git workflow
1. `git switch main && git pull`, then `git switch -c feat/<short-name>` (or `fix/…`).
2. Commit small, with clear messages (`feat: add robotics events`, `fix: gallery caption overflow`).
3. `git push -u origin feat/<short-name>` and open a PR into `main`. Fill in the template, including desktop and phone screenshots.
4. CI must be green and the preview deploy must look right. A code owner approves, then squash-merge.
5. Keep your branch fresh with `git pull --rebase origin main`.
